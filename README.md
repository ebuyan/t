# tinvest

Выгрузка портфеля из T-Invest API в файлы Obsidian. Один бинарник без внешних
зависимостей, две независимые задачи по своим расписаниям:

| Задача | Что делает | Когда |
| --- | --- | --- |
| Реестр доходности | Запись в начало `Реестр.md` + бары прогресса в `Портфель.md` | Пн и Пт в 11:00 |
| Срез долей | Добавляет столбец в таблицы `Портфель.md` | 1 число квартала |

Задачи работают в отдельных горутинах: срез долей обходит два десятка инструментов
и не должен сдвигать запись в реестр.

## Реестр доходности (`Реестр.md`)

Дописывает в **начало** файла запись в формате inline-полей Dataview:

```
- date:: 2026-07-20
  income:: -1012000
  stock:: -1112000
  gold:: -101000
  dividends:: 201000
  realty:: -12000
```

- `stock` — абсолютная доходность по акциям за всё время
- `gold` — то же по золоту
- `dividends` — накопленные с начала истории выплаты за вычетом налога: дивиденды
  Т-Банка и выплаты по бумагам и паям на Финаме
- `realty` — курсовая доходность недвижимости (паи ЗПИФ на Финаме, `unrealized_pnl`)
- `income` — их сумма

Источник `stock`/`gold` — `positions[].expectedYield` из `GetPortfolio`, разбитый по
классам активов. Готового поля с абсолютной прибылью в ответе нет; сходимость
проверена на реальном портфеле: сумма, делённая на вложенное (кол-во × средняя
цена), даёт ровно тот процент, что API отдаёт в `expectedYield`. Выплаченные
дивиденды в `expectedYield` не входят (приходят деньгами), поэтому берутся отдельно
из истории операций — см. `/api/today` ниже. Если история выплат ещё не собрана,
запись пропускается: `income` без дивидендов испортил бы ряд.

Порядок строк — часть контракта с волтом: `График.md` и `Сравнение с IMOEX.md`
разбирают блок текстом по номерам строк (0–3: date, income, stock, gold), поэтому
новые поля дописываются только в конец: `dividends`, затем `realty`.

Числа округляются **вверх до тысячи** — математически, то есть к нулю для
отрицательных: `-1 162 021 → -1 162 000`, но `1 162 021 → 1 163 000`. `income`
считается уже от округлённых слагаемых, иначе в файле нарушился бы инвариант
`income = stock + gold + dividends + realty`.

Повторный запуск в тот же день обновляет запись на месте, а не добавляет вторую.

### Бары прогресса в `Портфель.md`

Заодно с записью в реестр (Пн и Пт, а также по кнопке «Записать в реестр») задача
обновляет блоки ` ```progressbar ` в `Портфель.md` — прогресс накопления к цели:

```progressbar
kind: manual
name: Total
goal: 10000
max: 100
value: 47
width: 100%
```

- `value` = накоплено ÷ цель × 100, `max` всегда `100` (бар в процентах).
- `goal` — **цель в тысячах рублей**, правится вручную в Obsidian; задача её не
  трогает. Поле обязательно: без `goal` (или с нечисловым значением) бар
  пропускается, а не переписывается.
- Бар выбирается по `name` (регистр не важен): `Total` — полный портфель
  (Т-Банк и Финам), `Stoc` — акции, `Gold` — золото, `Reits` — недвижимость (паи
  ЗПИФ на Финаме), `Cash` — свободные рубли и LQDT. Блоки с другими `name`, а также
  `kind`, отличный от `manual` (напр. `day-year`), не трогаются.

Обновляются только строки `goal`/`max`/`value` нужных блоков; остальной файл (текст,
таблицы, прочие блоки) сохраняется байт-в-байт. Повторный прогон с теми же данными
ничего не меняет.

## Срез долей (`Портфель.md`)

Раз в квартал дописывает столбец во все таблицы файла с долями активов.
Таблицы опознаются по заголовку первого столбца:

| Таблица | Что считается |
| --- | --- |
| `Актив` | Доли акций, золота, недвижимости и кеша, плюс итог в рублях |
| `Компания` | Доля каждой бумаги от общей базы |
| `Сектор` | Доли секторов, нормированные к акциям (в сумме 100%) |
| `Дивиденды` | Столбец текущего года, обновляется на месте |

### База расчёта

Доли в таблицах «Актив» и «Компания» считаются от **акции + золото + недвижимость +
кеш** — классы в сумме дают ровно 100%. Строка «Недвижимость» появляется в таблице
при первом срезе после подключения Финама, сразу под «Золото»; в прошлых столбцах у
неё прочерк. Секторы нормируются к акциям.

Золото — это `GLDRUB_TOM`: API отдаёт его как `instrumentType: "currency"`, то есть
внутри `totalAmountCurrencies`, отдельного класса активов в контракте нет. Список
таких тикеров — `goldTickers` в `snapshot.go`.

Дивидендная доходность — сумма полей `yieldValue` по всем выплатам `GetDividends`
за календарный год. Это доходность к цене закрытия на дату объявления, и ровно её
показывает приложение Т-Инвестиций — цифры в таблице совпадают с приложением.

Считать самим (сумма выплат к текущей цене) было бы не то же самое: после отсечки
цена падает, и доходность к ней получается выше. Пример на 20.07.2026, SBERP:
выплата 37,64 ₽ при цене объявления 279,92 ₽ даёт 13,44% (как в приложении), а к
текущей цене 258,67 ₽ вышло бы 14,55%.

### Сопоставление строк

Строки сопоставляются с позициями по тикеру — части подписи до `—`. Написанные
вручную названия при этом не перезаписываются названиями из API: в существующую
строку просто добавляется значение в новый столбец.

Отсюда требование: тикер в файле должен совпадать с тикером Т-Банка. Если написать
`SBER`, когда в портфеле лежит `SBERP`, строка не сопоставится и рядом появится
вторая — с тем же активом и пустой историей.

Повторный запуск в тот же день не плодит столбцы: существующий столбец с той же
датой обновляется на месте. Строки выбывших активов получают `—`, новые активы
дописываются в конец таблицы.

## Веб-страница доходности

На `TINVEST_HTTP_ADDR` (по умолчанию `:8080`) отдаётся HTML-страница с текущей
доходностью: общая стоимость портфеля, **изменение за сегодня** (абсолютное и в процентах — сумма
`dailyYield` по счетам Т-Банка и `daily_pnl` позиций Финама), абсолютный и
относительный доход за всё время (переоценка позиций плюс полученные выплаты,
выплаты — отдельной строкой под суммой), карточки акций, золота и недвижимости и
таблица состава (бумаги, фонды, золото и свободный кеш одной таблицей, с колонками цены за штуку,
стоимости, доли, дохода за всё время и изменения за сегодня). По строке «Кеш» видно
приход дивидендов.
Данные берутся из лёгкого минутного кеша (названия бумаг — из часового кеша
метаданных, по возможности); страница сама обновляется раз в минуту
(`<meta http-equiv="refresh">`).

Если задан `TINVEST_REGISTRY_FILE`, на странице есть кнопка **«Записать в реестр»**:
по нажатию `POST /sync/registry` дописывает текущий срез в реестр доходности тем же
кодом, что и задача по расписанию (идемпотентно — повторная запись за тот же день
обновляет запись на месте). `GET /healthz` — liveness-проба.

`GET /api/today` отдаёт JSON-сводку «всего за сегодня» из того же минутного кеша —
для внешних потребителей (напр. виджета в меню-баре macOS). Без авторизации, как и
страница. Числа — в рублях, `day_change_pct` — в процентах:

```json
{ "portfolio_value": 1234567.00, "total": 1200000.00, "day_change": 4321.00,
  "day_change_pct": 0.35, "income": 234567.00, "dividends": 45678.00,
  "shares": { "value": 800000.00, "yield": 200000.00 },
  "gold": { "value": 100000.00, "yield": 40000.00 },
  "realty": { "value": 300000.00, "yield": -5433.00 },
  "cash": 34567.00,
  "holdings": [
    { "class": "shares", "ticker": "SBERP", "name": "Сбербанк", "value": 90000.00, "day_change": 120.00 },
    { "class": "realty", "ticker": "RU000A1034U7", "name": "Акцент 5", "value": 300000.00, "day_change": -344.00 },
    { "class": "gold", "ticker": "GLDRUB_TOM", "name": "Золото", "value": 100000.00, "day_change": 50.00 }
  ],
  "updated": "2026-07-23T18:30:00+03:00" }
```

`total` — вложенное в доходные активы (акции + золото + недвижимость, без кеша).
`class` у строки состава — `shares`, `gold` или `realty`: по нему виджет раскладывает
бумаги в подменю классов.

`income` — курсовая переоценка позиций (акции + золото + недвижимость) за всё время:
выплаты в неё не входят, потому что приходят деньгами и в доходность позиций не
попадают. `dividends` — полученные за всё время выплаты за вычетом удержанного
налога: дивиденды Т-Банка и выплаты по бумагам и паям на Финаме (история операций,
часовой кеш). Полный доход за всё время =
`income + dividends`, доходность к вложенному — `(income + dividends) / (total −
income)`; так считает виджет меню-бара. Пока история выплат не собрана,
`dividends` равен нулю — сводка без них полезнее ошибки.

## Счета Финама (недвижимость)

Если задан `FINAM_TOKEN`, в срез добавляются счета Финама через Finam Trade API
(REST, `https://api.finam.ru`). Там лежат паи ЗПИФ коммерческой недвижимости.

- **Токен.** Секрет выпускается в личном кабинете Финама, раздел «Токены». Клиент
  сам меняет его на JWT (`POST /v1/sessions`), держит JWT 10 минут из 15 и
  перевыпускает после ответа 401. Список счетов берётся из токена
  (`/v1/sessions/details`).
- **Классы.** Всё, что на Финаме не золото (`goldTickers`) и не LQDT
  (`cashTickers`), считается **недвижимостью**. Стоимость — `quantity ×
  current_price`, доход — `unrealized_pnl`, изменение за день — `daily_pnl`.
  Рублёвый кеш счёта идёт в «Кеш». Если на Финам придут акции, классификацию нужно
  уточнять по типу инструмента.
- **Выплаты.** Из истории транзакций берутся доходы (`INCOME`) с привязкой к бумаге
  и налоги (`TAX`) по тем же бумагам. История выгружается помесячными окнами с даты
  открытия счёта, раз в час, и складывается с дивидендами Т-Банка.
- **Названия фондов** берутся из `GET /v1/assets/{symbol}` раз в час, вместе с
  метаданными.
- **Ошибка Финама — ошибка всего среза.** Неполный срез испортил бы доли и реестр,
  поэтому кеш в это время отдаёт прошлый целый срез.

Контракт взят из официального swagger и proto Финама
([FinamWeb/finam-trade-api](https://github.com/FinamWeb/finam-trade-api)). На живом
счёте с позициями он ещё не проверен: счёт пока пуст.

## Безопасность записи

Оба файла живут в синкающемся волте, поэтому запись устроена одинаково:

1. Файл читается и разбирается; всё, что не таблица и не запись, не трогается.
2. Новое содержимое пишется во временный файл в том же каталоге и переносится
   поверх через `rename` — оборванная запись не оставит половину файла.

Тот же каталог для временного файла обязателен: `rename` атомарен только в пределах
одной файловой системы.

## Переменные окружения

| Переменная | Обяз. | Описание |
| --- | :---: | --- |
| `TINVEST_TOKEN` | ✓ | Токен T-Invest API (достаточно read-only) |
| `FINAM_TOKEN` |  | Секрет Finam Trade API; без него счета Финама (недвижимость) не подтягиваются |
| `TINVEST_REGISTRY_FILE` |  | Реестр доходности (`Реестр.md`) |
| `TINVEST_REGISTRY_SCHEDULE` |  | Когда обновлять реестр: `Mon,Fri 11:00` или `11:00` для ежедневного |
| `TINVEST_PORTFOLIO_FILE` |  | Файл с таблицами долей (`Портфель.md`) |
| `TINVEST_PORTFOLIO_SCHEDULE` |  | Время `HH:MM` обновления долей первого числа квартала |
| `TINVEST_HTTP_ADDR` |  | Адрес веб-страницы доходности, по умолчанию `:8080` |
| `TZ` |  | Часовой пояс для расписания, напр. `Europe/Moscow` |

Сервис всегда поднимает веб-страницу доходности (`TINVEST_HTTP_ADDR`, по умолчанию
`:8080`) и, если заданы расписания, дописывает файлы по ним. Данные собираются
фоном в кеш, из которого читают и страница, и задачи по расписанию, так что в API
мы не ходим на каждый запрос и каждое срабатывание. Кеш трёхуровневый: лёгкий срез
(`GetPortfolio`: стоимости и доходность) обновляется **раз в минуту** — его хватает
странице и реестру; тяжёлые метаданные (названия, секторы, дивидендная доходность —
`ShareBy` + `GetDividends` на каждую бумагу) меняются редко и обновляются **раз в
час**, они нужны только квартальному срезу долей; история выплаченных дивидендов
(`GetOperationsByCursor` с даты открытия счёта) — тоже **раз в час**, она меняется
всего несколько раз в год.

Отдельного разового режима нет: процесс всегда работает как сервис. Записать
текущие значения в реестр вне расписания можно кнопкой на веб-странице.

Ошибка отдельного прогона логируется, но не роняет процесс: иначе
`restart: unless-stopped` увёл бы контейнер в цикл перезапусков.

Токен выпускается в приложении Т-Инвестиций: *Настройки → Токен для T-Invest API*.
Достаточно токена **только для чтения** — приложение не делает торговых вызовов.

## Структура

```
cmd/tinvest      — точка входа: конфиг, кеш, обвязка serve, задачи по расписанию
internal/tinvest    — клиент T-Invest API, модели и денежный тип Dec
internal/finam      — клиент Finam Trade API (REST): JWT, счёт, транзакции, инструмент
internal/portfolio  — домен: сбор среза и метаданных, кеш, запись md-файлов, веб-модель
internal/server     — HTTP-сервер: страница доходности, синхронизация в реестр, healthz
web                 — статика: HTML-шаблоны страницы, встроены через go:embed
```

## Сборка и запуск

```sh
go build -o tinvest ./cmd/tinvest
# кросс-компиляция под сервер (Linux x86-64):
make build
```

```sh
export TINVEST_TOKEN=…

# только веб-страница на :8080 (без записи файлов)
./tinvest

# со всеми задачами по расписанию и своим адресом
TINVEST_HTTP_ADDR=":9000" \
TINVEST_REGISTRY_FILE="/mnt/vault/Финансы/Портфель/Реестр.md" \
TINVEST_REGISTRY_SCHEDULE="Mon,Fri 11:00" \
./tinvest
```

Берутся все брокерские счета и ИИС. Перед первым запуском на живом файле стоит
прогнать на копии и посмотреть diff (либо нажать кнопку записи в реестр на странице
и проверить результат).

### В стеке ha (192.168.0.108)

Блок для `~/ha/docker-compose.yaml` — в стиле сервиса `energo`:

```yaml
  tinvest:
    build: https://github.com/ebuyan/t.git#main
    container_name: tinvest
    restart: unless-stopped
    environment:
      TINVEST_TOKEN: "…"
      FINAM_TOKEN: "…"   # необязательно: счета Финама (недвижимость)
      TINVEST_REGISTRY_FILE: "/vault/Финансы/Портфель/Реестр.md"
      TINVEST_REGISTRY_SCHEDULE: "Mon,Fri 11:00"
      TINVEST_PORTFOLIO_FILE: "/vault/Финансы/Портфель/Портфель.md"
      TINVEST_PORTFOLIO_SCHEDULE: "10:00"
      TINVEST_HTTP_ADDR: ":8077"
      TZ: "Europe/Moscow"
    ports:
      - "8077:8077"   # веб-страница доходности; правая часть = порт из TINVEST_HTTP_ADDR
    volumes:
      - ./data:/vault
```

`TINVEST_HTTP_ADDR` (`:8077`) слушает все интерфейсы внутри контейнера; чтобы
страница открывалась снаружи по `http://192.168.0.108:8077`, порт надо ещё
опубликовать блоком `ports` — правая часть `8077:8077` должна совпадать с портом из
`TINVEST_HTTP_ADDR`.

`./data` — тот же каталог, который раздаёт `dufs` на `file.buyan.fun`, то есть волт,
синкающийся из Obsidian по WebDAV. Пути в переменных указываются **внутренние**
(от `/vault`). Если волт лежит в подкаталоге `./data`, монтирование стоит сузить до
него — контейнеру не нужен доступ на запись ко всему файловому серверу.

`TZ` обязателен: в контейнере время идёт по UTC, и без него расписание сработает
на три часа раньше.

```sh
docker compose up -d --build tinvest
docker compose logs -f tinvest
```

Страница доходности после старта — на `http://192.168.0.108:8077`. Записать текущие
значения в реестр вне расписания можно кнопкой на ней.

## TLS и сертификат НУЦ Минцифры

`*.tbank.ru` выпущен удостоверяющим центром Минцифры («Russian Trusted Root CA»),
которого **нет** в стандартных хранилищах доверия — ни в alpine, ни в macOS. Без него
любой запрос падает с `x509: certificate signed by unknown authority`.

Корневой сертификат вшит в бинарник (`russian_trusted_root_ca.pem`, `go:embed`) и
добавляется **только в пул этого HTTP-клиента** — системное хранилище не изменяется,
на остальные приложения хоста доверие не распространяется (`internal/tinvest/client.go`).
